01 / EXECUTIVE SUMMARY

ภาพรวมโครงการ

FIREKEEPER Core พัฒนาต่อยอดจากแนวคิด PUNN Cognitive Architecture (PCA) เพื่อช่วยจัดโครงสร้างการวิเคราะห์ของ AI ประเมินหลักฐาน แสดงความไม่แน่นอน และรักษาอำนาจการตัดสินใจขั้นสุดท้ายไว้กับมนุษย์

ขอบเขตหลักฐาน: การมีแนวคิด การมีโค้ด การทดสอบผ่าน และการตรวจรับรองจากภายนอก เป็นสถานะที่แตกต่างกัน เอกสารนี้ไม่ใช่ใบรับรองความปลอดภัยหรือการประเมินมูลค่าธุรกิจอย่างเป็นทางการ

02 / PROJECT LINEAGE

จากแนวคิดสู่สอง Repository

1 กุมภาพันธ์ 2569 · Concept Formation

วันที่เริ่มต้นโครงการตามข้อมูลของผู้สร้าง ครอบคลุมช่วงที่ PCA ยังเป็นแนวคิดก่อนมี Repository ไม่ใช่วันที่ยืนยันจาก Git Commit และไม่ใช่หลักฐานว่ามีการทำงานทุกวัน

PUNN Cognitive Architecture ↗

Repository รากฐานที่อธิบาย Cognitive Layer สำหรับจัดลำดับ Observation, Understanding, Purpose, Memory, Mental Model, Hypothesis, Evidence Evaluation, Critique, Decision, Communication, Reflection และ Learning โดยไม่ต้องปรับน้ำหนักโมเดลภาษาโดยตรง

FIREKEEPER Core ↗

Repository แอปพลิเคชันที่ขยายแนวคิดไปสู่ React Workspace, Express Backend, Governance Workflow, Evidence States, Confidence Assessment และ Audit Functionality

Repository แรกเผยแพร่ภายใต้ MIT License และ Repository ที่สองภายใต้ Apache License 2.0 ความเชื่อมโยงเชิงแนวคิดไม่ใช่หลักฐานการสืบทอดโค้ดระดับไฟล์ทุกส่วน

05 / EVIDENCE & AUDIT

หลักฐาน ความมั่นใจ และการตรวจสอบย้อนหลัง

ระบบแยกข้อเท็จจริงที่มีหลักฐานรองรับออกจากสมมติฐาน ข้ออนุมาน และข้อมูลที่ยังไม่เพียงพอ สูตร Confidence ตามเอกสารโครงการคือ C = 0.40 × Coverage + 0.35 × Reliability + 0.25 × Quality − Penalties โดยแสดง N/A เมื่อหลักฐานไม่เพียงพอ คะแนนดังกล่าวไม่ใช่ความน่าจะเป็นที่คำตอบถูกต้องโดยอัตโนมัติ

Hash Chaining และ Merkle Root สามารถสนับสนุนการตรวจจับการเปลี่ยนแปลงข้อมูล แต่ไม่ได้ทำให้ระบบจัดเก็บทั้งหมดเป็น Tamper-Proof โดยลำพัง

06 / SECURITY

Data Persistence และขอบเขตความปลอดภัย

Modeแนวทางตามเอกสารโครงการ
Offlineจัดเก็บ Conversation, Memory และ Settings ภายในอุปกรณ์ผู้ใช้
Hostedมีการจัดเก็บ Conversation, Memory และ Audit Records ผ่าน Backend ตามการตั้งค่า Retention
BYOKAPI Key ที่ผู้ใช้ระบุถูกเก็บใน Browser Local Storage และใช้กับคำขอของ Provider ที่เลือก

Hosted Mode ไม่ใช่ Zero-Persistence และการตรวจสอบความปลอดภัยของ Production ต้องยืนยันทั้งโค้ด Configuration, Logs, Infrastructure และ Revision ที่ให้บริการจริง

07 / FINANCIAL ASSESSMENT

ต้นทุนจริงไม่ใช่มูลค่าธุรกิจ

Actual Cash Cost
≠ Founder Time Cost
≠ Replacement Cost
≠ Technology Asset Value
≠ Business Valuation

ช่วงเวลาประเมินตั้งแต่ 1 กุมภาพันธ์ – 22 กันยายน 2569 รวม 234 วันตามปฏิทินเมื่อนับวันแรกและวันสุดท้าย แต่ไม่ใช่ 234 วันทำงานที่ยืนยันแล้ว

รายการสถานะการประเมิน
Actual Cash Costยังไม่ยืนยัน ต้องตรวจใบเสร็จ API, AI Tools, Cloud และ Domain ตั้งแต่วันเริ่มต้น
Founder Time Costยังไม่ยืนยัน ต้องประมาณชั่วโมงทำงานจริงแยกตามระยะ
Replacement Costต้องกำหนดขอบเขต MVP และขอใบเสนอราคา ไม่ใช่ราคาขายของระบบ
Technology Asset Valueยังไม่ยืนยัน ต้องพิจารณาสิทธิ License คุณภาพ และความสามารถในการโอนสิทธิ
Business Valuationยังไม่ยืนยัน ต้องมีหลักฐานลูกค้า รายได้ ต้นทุน และเศรษฐศาสตร์ธุรกิจ

ตัวอย่างคำนวณต้นทุนเวลา — ไม่ใช่ชั่วโมงจริง

สมมติทำงานเฉลี่ย 1–4 ชั่วโมงต่อวันตลอด 234 วัน จะเท่ากับ 234–936 ชั่วโมง หากใช้อัตราสมมติ 300–500 บาทต่อชั่วโมง จะได้ 70,200–468,000 บาท ตัวเลขนี้เป็นเพียง Sensitivity Analysis ไม่ใช่ค่าใช้จ่ายที่จ่ายจริงหรือมูลค่าของสินทรัพย์

กรอบงบสร้างใหม่ที่เคยหารือกัน ได้แก่ 10,000–50,000 บาทสำหรับการสร้างเองด้วย AI Tools และ 100,000–350,000 บาทสำหรับการว่าจ้าง เป็นเพียงสถานการณ์วางแผนที่ยังไม่มีใบเสนอราคายืนยัน ไม่ควรนำไปแสดงเป็นราคาตลาดหรือมูลค่า FIREKEEPER
